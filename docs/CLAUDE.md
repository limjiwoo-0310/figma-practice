# 한국장학재단 누리집 정보전달 개선

요구사항 원문은 `docs/PRD.md`에 있다. 일정, 장학금 정보를 쉽게 찾게 해서 마감 시각 오인으로 인한 신청 누락을 막는 것이 목표다.

## 사용자

### 만드는 사람
- 코딩 초보자다. 설명은 한국어로, 전문 용어는 쉬운 말을 덧붙여 쓴다.
- 코드를 바꾼 뒤에는 무엇이 달라졌고 어떻게 확인하는지 알려 준다.
- 모르거나 애매한 부분은 추측해서 진행하지 말고 먼저 질문한다.

### 서비스를 쓰는 사람
- **대학생 김민준 (22세):** 마감 당일 저녁에 급하게 국가장학금을 신청한다. 마감 시각을 바로 확인하고 막힘없이 신청을 끝내고 싶어 한다.
- **학부모 이선영 (52세):** 신입생 자녀의 일정과 유의사항을 미리 챙긴다. 최신 지침인지 확신하고 서류, 가구원 동의 기한을 한눈에 보고 싶어 한다.

## 기술스택 (변경금지)

아래 기술은 바꾸지 않는다. 라이브러리를 추가하거나 다른 기술로 바꿔야 할 것 같으면 먼저 질문한다.

- React 19 + react-dom
- Vite 8 + `@vitejs/plugin-react`
- React Router 8 (`react-router`): 화면 이동
- JavaScript (JSX). TypeScript로 바꾸지 않는다.
- CSS 파일로 스타일 작성
- oxlint (코드 검사)

### 명령어
- `npm run dev`: 개발 서버 실행
- `npm run build`: 배포용 빌드
- `npm run lint`: 코드 검사
- `npm run preview`: 빌드 결과 미리 보기

## 디자인 규칙

### Figma
- 디자인은 추후 Figma MCP로 구현한다. 사이즈별 Figma 링크는 구현 단계에서 받는다.
- 링크를 받기 전에는 레이아웃 구조만 잡고, 세부 수치는 Figma를 받은 뒤 맞춘다.
- 데스크탑 콘텐츠 영역의 최대 너비(max-width)와 정렬 방식은 Figma 디자인을 따른다.

### 반응형
- 모바일: ~1279px / 데스크탑: 1280px~
- 모바일 우선으로 작성한다. 기본 스타일은 모바일 기준으로 쓰고, 데스크탑은 `@media (min-width: 1280px)`로 확장한다. `max-width` 미디어쿼리는 쓰지 않는다.
- 최소 지원 너비는 360px이다. 360px~1279px 어디에서도 레이아웃이 깨지지 않아야 한다.
- 모든 화면 너비에서 페이지에 가로 스크롤이 생기지 않아야 한다. 예외는 역할별 칩 목록뿐이며, 칩 목록 안에서만 가로 스크롤을 허용한다.

### 단위와 레이아웃
- 레이아웃은 Flexbox와 Grid로 구성한다.
- 레이아웃은 상대단위(%, rem)로 구성하고, 고정 px 너비는 쓰지 않는다. em 단위는 쓰지 않는다.
- 이미지와 미디어는 `max-width: 100%`, `height: auto`를 기본으로 하고, 비율 유지가 필요하면 `aspect-ratio`를 쓴다.
- 모바일에서 버튼과 링크의 터치 영역은 최소 2.75rem(44px) 이상으로 한다.

### 글과 강조
- 본문은 16~17px 이상, 줄 간격은 150% 이상으로 한다.
- 색상만으로 강조하지 않는다. 굵기, 아이콘, 배경 박스를 함께 쓴다.
- '소득인정액', 'ICL' 같은 전문 용어에는 쉬운 말을 함께 쓰거나 도움말을 제공한다.
- "09:00~24:00 (단, 마감 당일은 18:00까지)"처럼 괄호로 예외를 적지 않는다. 예외 조건은 별도 행의 짧은 문장으로 분리한다.

### 디자인 토큰
- 컬러, 폰트, 간격, 라운드, 그림자는 `src/styles/tokens.css`의 변수를 쓴다.
- 공지 목록 글자색은 `--color-text-body`를 쓴다.
- 달력 날짜는 Pretendard GOV로 쓴다. Figma에 SF Pro가 남아 있어도 `--font-calendar-day`, `--font-calendar-day-today`를 따른다.

## 서비스 구조

### 화면
1. **메인:** 마감 알림 카드(D-Day 배지와 CTA 버튼), 역할별 칩([신입생/재학생], [학부모]), 상태 배지가 붙은 정책 카드
2. **장학금 상세 및 통합 일정:** 최종 수정일, 수직 타임라인 카드, 아코디언, 하단 고정 CTA
3. **신청서 작성 및 서류 제출:** 진행 인디케이터(2/4 단계), 용어 도움말 바텀시트, 하단 5:5 분할 네비게이션

### 기능
- **F-01 상태 배지:** [진행중], [마감임박 D-0], [예정], [종료]를 기간에 따라 자동 표시한다. 마감 시각이 지나면 즉시 [종료]로 바꾸고 신청 버튼을 비활성화한다.
- **F-02 타임라인과 아코디언:** 일정은 1열 수직 카드로, 긴 안내문은 펼침/접힘으로 보여 준다. 데이터를 불러오는 동안 뼈대 화면(Skeleton)을 보여 준다.
- **F-03 하단 고정 CTA:** 스크롤과 관계없이 화면 맨 아래에 '신청하기' 버튼을 고정한다. 필수 동의를 빠뜨리고 누르면 해당 항목으로 포커스를 옮기고 오류 문구를 보여 준다.
- **F-04 용어 도움말:** 화면 이동 없이 바텀시트로 설명한다. 닫으면 입력 중이던 칸의 포커스를 유지한다. 바텀시트를 열지 못하면 텍스트 툴팁으로 대체한다.
- **F-05 최신성 표기:** 안내 콘텐츠 상단에 `최종 수정일: YYYY.MM.DD`를 표시하고, 마감된 배너는 메인에서 자동으로 숨긴다.

세부 수치와 규칙은 `docs/PRD.md`의 `4. 기능 요구사항`을 본다.

### 우선순위
1. **P0:** 일정 표기, 종료 정보 관리, 정보 위계
2. **P1:** 대출 비교와 진단, 현재 위치 안내, 맥락형 도움
3. **P2:** 색상 외 구분 수단, 모바일 최적화

### 코드 위치
- `index.html`: 앱이 시작되는 HTML
- `src/main.jsx`: React 시작점
- `src/App.jsx`: 최상위 컴포넌트
- `src/index.css`: 전역 스타일 진입점. fonts → tokens → reset → base 순서로 불러온다.
- `src/styles/fonts.css`: 웹폰트 등록 (`src/fonts`의 Pretendard GOV)
- `src/styles/tokens.css`: 디자인 토큰
- `src/styles/reset.css`: 브라우저 기본 스타일 초기화
- `src/styles/base.css`: body, 제목, 링크 기본 스타일
- `src/components/`: 공통 컴포넌트. 종류별 하위 폴더에 두고, CSS 파일은 컴포넌트와 같은 폴더에 같은 이름으로 둔다 (예: `button/Button.jsx`, `button/Button.css`).
  - `button/`: 버튼
  - `card/`: 카드와 카드 안의 부품
  - `form/`: 입력과 선택 (검색창, 동의 버튼)
  - `icon/`: 아이콘
  - `layout/`: 푸터, 페이지 제목 등 화면의 큰 틀
  - `navigation/`: 메뉴, 링크 묶음, 위치 표시, 단계 표시
  - `overlay/`: 화면 위에 뜨는 팝업
- 컴포넌트, 클래스, 파일, 변수, prop 값 이름은 영어로 쓴다. Figma 이름을 뜻대로 옮긴다 (예: `메뉴바/데스크탑` → `MenuBarDesktop`, `.menu-bar-desktop`). 화면에 보이는 문구와 주석은 한국어로 쓴다.
- Figma의 `L` 버튼은 `Button`으로 만들어 두었으니 그것을 쓴다.
- 이미지는 PNG나 JPG로 받는다.
- `src/pages/`: 화면. 메인(`/`), 신청가이드 4개(`/guide/*`), 신청서 작성과 완료 5개(`/apply/*`)
- `src/utils/schedule.js`: 일정 상태 계산 (F-01)
- `src/hooks/`: 현재 시각(`useNow`), 불러오기 흉내(`useExampleLoading`)
- `src/data/exampleData.js`: 예시 데이터. Figma의 자리표시 값이며 실제 일정이 아니다.
- `src/assets/icons/`: 아이콘 (사이트 아이콘, 방향 아이콘, SNS 아이콘 등)
- `src/assets/images/`: 아이콘이 아닌 그림 (메뉴 이미지, 로고, 배너, 카드 사진 등)
- `docs/PRD.md`: 요구사항 문서

### 데이터
- 실제 API 없이 예시 데이터 파일을 쓴다. 파일은 `src/data/`에 둔다.
- 일정, 마감 시각 등은 실제 값이 아니라 예시임을 파일에 분명히 표시한다.

## 안전규칙

- 이 폴더는 git 저장소가 아니라 지운 파일을 되돌릴 수 없다. 파일을 삭제하거나 통째로 덮어쓰기 전에 먼저 확인받는다.
- 배포, 커밋, 패키지 설치와 삭제는 요청받았을 때만 한다.
- 비밀번호, API 키, 토큰을 코드에 넣지 않는다.
- 실제 개인정보(이름, 주민등록번호, 소득 정보 등)를 코드나 예시 데이터에 쓰지 않는다.
- 장학금 일정, 마감 시각, 자격 조건을 지어내지 않는다. 확인되지 않은 값은 예시 데이터임을 분명히 표시하고, 실제 값은 질문한다.
- 작업이 끝나면 `npm run lint`와 `npm run build`를 실행하고, 실패하면 숨기지 말고 그대로 알린다.
